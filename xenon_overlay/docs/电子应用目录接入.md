# Electron 应用目录接入

## 本地应用制品与源码仓库

以下两个目录是开发者在本机生成并导入的应用制品，已由 `.gitignore` 忽略，**当前版本不再由 Git 跟踪，新的检出需自行生成**：

- `xenon_overlay/resources/thunder_2025/`
- `xenon_overlay/resources/xenon_player/`

本仓库继续跟踪目录之外的 `*.xenon.json` 接入声明与 `*.asar-public-key.pem` 公钥。`xenon_player.release-manifest.json` 仅保留此前已验证版本的来源和哈希记录，不能作为新导入内容的当前清单；每次导入用 `--manifest` 在 `out/` 下生成本地清单。

| 应用 | 源码与生成流程 |
| --- | --- |
| TH | [thunder_2025 源码仓库](https://new-gitlab.xunlei.cn/xl_client/thunder_2025)，按 [TH 制品准备](./thunder_2025接入Electron容器.md#21-从源码生成并导入windows发行目录) 生成完整发行目录。 |
| PLE | [xmp_xdas_2 源码仓库](https://new-gitlab.xunlei.cn/xl_client/xmp_xdas_2)，已验证基线为 `7.1.35_173-win-channel`；按 [PLE 制品准备](./xenon-player接入Electron播控.md#21-从源码生成并导入windows发行目录) 构建并组装。 |

这些内部仓库及其子模块、私有包需要相应访问权限。应用编译、版本写入、签名及 SDK 组装由各自源码仓库负责；本仓库的导入工具只接收完整发行目录。

`xenon_electron_apps` 默认是 `[]`，浏览器构建和安装包默认不包含应用。导入本地目录后，还需按下文显式选择要附带的应用；所选目录缺失会在 `gn gen` 时报错，复制或目录一致性校验失败也不会被当作“未选择该应用”而忽略。

## 侧栏原包测试入口

侧栏在 TH 后提供以下入口，使用同一个通用描述文件加载和容器激活流程。
首次点击启动应用，后续点击激活已运行窗口；应用退出后可再次启动。

| 按钮 | 应用 | 本地发行目录 | 外置声明 |
| --- | --- | --- | --- |
| DIO | draw.io | `xenon_overlay/resources/drawio/` | `drawio.xenon.json` |
| MT | MarkText | `xenon_overlay/resources/marktext/` | `marktext.xenon.json` |
| MX | Motrix | `xenon_overlay/resources/motrix/` | `motrix.xenon.json` |

三个目录保存随仓库跟踪的、经过验证的 Windows x64 宿主制品；相邻
`*.release-manifest.json` 记录官方来源、保留文件与删除清单。它们移除了重复 Electron
引擎，应用 ASAR、native/helper 和许可证保持原字节，不再作为独立 Electron 程序运行。
具体边界见 [宿主裁剪评估](Electron示例应用宿主裁剪评估.md)。三个 `resources/app.asar`
由 Git LFS 存储，避免超过 GitHub 单文件限制，检出后仍为完整原始归档。安装 Git LFS 后，
在仓库根目录执行以下命令（远端名按本地配置调整）：

```powershell
git lfs install --local
git lfs pull --include="xenon_overlay/resources/drawio/resources/app.asar,xenon_overlay/resources/marktext/resources/app.asar,xenon_overlay/resources/motrix/resources/app.asar" --exclude="" my_fork
```

跳过 LFS 下载时，工作区只有指针文本，不能用来运行或打包应用。本地 GN 配置仍须选择
需要附带的应用，例如：

```gn
xenon_electron_apps = [ "thunder_2025", "xenon_player", "drawio", "marktext", "motrix" ]
```

外置声明仅包含相对 `application` 路径，不绑定开发者盘符或工作目录。
现有构建复制规则将所选原包和声明放入输出目录；不修改 ASAR、应用入口或
依赖。未导入的应用无法通过侧栏启动，错误原因记录到浏览器日志。
默认构建不自动下载这些发行包；VS Code 不在侧栏或当前验证目标中。

## 导入契约

导入的对象是**已经组装完成、版本一致的发行目录**。适配层保留输入目录内的所有相对文件路径和文件字节，最终打包输出也应保持同一布局。

`tools/import_electron_app.py` 是通用导入工具，没有应用名称、可执行文件名称或 native 文件名分支。它：

- 原样复制 ASAR、加密 ASAR、`.asar.unpacked`、`.node`、DLL 和其他发行文件；不解包、不重打、不修补 JavaScript。
- 不把 native 同时复制到根目录、`build/`、`build/Release/`，也不拆分 main、preload 和 renderer。
- 记录空目录，按相对文件路径、长度及 SHA-256 检查结果；不靠时间戳判定内容一致。
- 明确拒绝 symlink、Windows junction、其他 reparse point 以及普通文件/目录之外的对象。当前版本不支持链接保留，不能通过跟随链接或展开目标来悄悄改变布局。
- 要求导入期间输入目录稳定；输入变化或复制结果不一致时，在替换前失败。

该工具确认导入完整性，不代替应用发布验证：它不会解密归档来验证 `main`，也不会加载 `.node` 判断 ABI、检查插件配置是否缺件，或证明供应方二进制来自某个提交。

## 使用方式

可以使用供应方已经发布的、与本机平台和架构匹配的完整发行目录，也可以从应用源码生成。
直接运行现成目录不需要导入或重打包；只有需要随宿主分发时，才在本仓库源码根目录运行导入工具：

```powershell
python xenon_overlay/tools/import_electron_app.py `
  --src F:/releases/example/1.2.3 `
  --out H:/chromium_142/src/xenon_overlay/resources/example `
  --manifest H:/chromium_142/src/out/import-manifests/example.json
```

`--out` 是**目标应用目录本身**，不是多个应用的公共父目录。目标旧目录会在新目录复制、哈希校验完成后被整体替换，因此旧发行中已删除的文件不会残留。

本仓库忽略 TH、PLE 两个本地生成制品目录。draw.io、MarkText、Motrix 的已验证宿主制品
允许提交，目录属性禁止 Git 换行转换。其他应用若导入 `xenon_overlay/resources/example/`，
需先明确是否跟踪；仅本地使用时加入 `.git/info/exclude` 或受审查的 `.gitignore`。
三个公开应用更新时应重新审查官方发行包、更新来源清单并验证，不能直接套用旧版本裁剪清单。

工具识别并记录以下入口候选，保留原始 `package.json`：

| 输入布局 | 检测标志 |
| --- | --- |
| Electron 发行目录，应用为归档 | `resources/app.asar` |
| Electron 发行目录，应用为目录 | `resources/app/package.json` |
| 无链接的 macOS bundle | `Contents/Resources/app.asar` 或 `Contents/Resources/app/package.json` |
| 单独的应用目录 | 根目录 `package.json` |

同一目录有多个候选时，清单记录所有候选，不猜测厂商定制启动器的优先顺序。归档保持不透明；例如 `resources/app/package.json` 指向 `out.asar/main.js` 时，`out.asar` 仍只是被原样复制的发行文件。

`--manifest` 可选。清单必须位于源目录和目标目录之外，避免宿主记录成为应用负载的一部分。清单包含检测到的布局、源/目标路径，以及所有相对文件路径、大小、SHA-256 和目录；不包含文件正文。

导入后或最终打包后进行只读比较：

```powershell
python xenon_overlay/tools/import_electron_app.py `
  --src F:/releases/example/1.2.3 `
  --out H:/chromium_142/src/out/Release_64/example `
  --check
```

一致返回退出码 `0`；有增删、内容变化、目录差异或读取错误时返回非零。`--check` 不复制文件、不生成清单，可用于验证资源目录与最终输出目录完全一致。不能同时使用 `--check` 和 `--manifest`。

旧脚本名保留为薄入口：

```powershell
python3 xenon_overlay/tools/sync_thunder_2025.py --src F:/releases/thunder --out xenon_overlay/resources --manifest out/import-manifests/thunder_2025.json
python3 xenon_overlay/tools/sync_xenon_player.py --src F:/releases/player --out xenon_overlay/resources --manifest out/import-manifests/xenon_player.json
```

这两个入口的 `--out` 为父目录，分别导入其下的 `thunder_2025` 和 `xenon_player`；不传时使用仓库的 `xenon_overlay/resources`。`--src` 现为必填的完整发行目录。旧 `--player-sdk`、`--native-dir`、`--plugins-dir`、重打归档及忽略文件等参数会直接报错。`sync_xenon_player_frontend.py` 已退役，执行只返回错误及完整目录导入指引，不会创建 `frontend/`。

## 外置宿主配置

导入清单记录复制结果；宿主配置控制如何启动应用，两者用途不同。工具不生成或改写宿主配置，也不把宿主配置、公钥自动塞进应用目录。

启动入口接受绝对路径：

```powershell
xlb153.exe --xenon-electron-app=H:/applications/example
xlb153.exe --xenon-electron-app=H:/applications/example/resources/app.asar
xlb153.exe --xenon-electron-app=H:/applications/example.xenon.json
```

无需覆盖入口或其他宿主配置时可直接使用发行目录、应用目录或 ASAR。需要覆盖时，在应用目录外提供 JSON，例如：

```json
{
  "application": "example",
  "executable": "example/application.exe",
  "main": "out.asar/main.js",
  "archivePublicKey": "example.asar-public-key.pem"
}
```

| 字段 | 含义及路径基准 |
| --- | --- |
| `application` | JSON 配置必填；发行目录、应用目录或 ASAR。相对路径基于 JSON 所在目录。 |
| `executable` | 可选的已存在应用可执行文件，用于应用身份及路径语义；相对路径基于 JSON 目录。不指定时使用宿主可执行文件。 |
| `main` | 可选入口覆盖，相对于解析后的应用根目录；例如发行根解析到 `resources/app` 后，`out.asar/main.js` 在该 app 目录内。 |
| `archivePublicKey` | 可选公钥文件，相对路径基于 JSON 目录。只接受运行时支持格式的公钥，不需要私钥。 |
| `name`、`version` | 可选名称和版本覆盖，默认来自应用元数据。 |
| `userDataPolicy` | 可选 `isolated`（默认）或 `legacy-host`。前者将应用普通文件放在宿主 `User Data/ElectronApps/<身份 SHA-256>/UserData`；后者显式保留历史宿主根目录。不会复制、删除或移动旧文件。 |
| `storageId` | 可选稳定、非空字符串（最多 256 UTF-8 字节，不含 NUL），仅用于持久文件身份。优先于宿主声明的非 `default` 容器 ID；无两者时使用规范化安装路径。安装路径随版本变化的裸命令行接入应声明固定 ID，避免升级被视为另一安装。不得将显示名当作唯一 ID。 |
| `nativeAddonExecution` | 可选 `standard`（默认）或 `shared`。`standard` 的 main 在自身 V8 上下文加载 `.node`，保留同步回调、异常及对象身份；`shared` 让 main 与 renderer 使用同一个原生执行器及模块实例。运行期间不允许切换。 |
| `versionFromExecutable` | 可选布尔值；开启后从应用可执行文件读取版本，覆盖 `version`。平台或文件无法提供版本时会报错，不自动猜测。 |
| `parentWindowPairing` | 可选字符串数组，声明需要与父窗配对的页面路径。路径相对于解析后的应用根目录。 |
| `privilegedSchemes` | 可选协议声明数组，格式与 Electron `protocol.registerSchemesAsPrivileged` 参数一致。当前实际支持 `standard`、`secure`、`supportFetchAPI`、`corsEnabled`、`bypassCSP`；`codeCache` 接受声明但不启用缓存，`allowServiceWorkers: true` 和 `stream: true` 明确拒绝。必须在宿主启动前配置。 |

`main` 和 `parentWindowPairing` 必须是应用内相对路径，不允许绝对路径或 `..`。加载器拒绝未知字段和错误字段类型。应用本身的 `package.json`、ASAR、preload、`.node` 保持发行字节不变。

`userData` 的默认隔离不改变已有 Chromium `sessionData` 分区位置；首次使用会话前
显式调用 `app.setPath` 仍可重定向，两项路径的冻结与独立设置规则见
[应用数据目录设计](Electron应用数据目录重定向设计.md)。启动时在后台创建默认
`userData`，成功后才启动应用主进程，失败明确终止本次启动。TH、PLE、draw.io、
MarkText、Motrix 的现有接入配置声明 `legacy-host` 以保留存量文件；新接入配置应
采用默认隔离策略。切换策略不会自动迁移数据，维护者须明确选择及安排迁移。

保留完整发行布局不等于支持任意 Electron 应用。应用依赖的 Electron/Node API 必须已由兼容层实现，native 模块也必须与当前运行时 ABI 兼容；导入器不补写不存在的 API，也不转换 native 二进制。

原生模块执行模式不按应用名或模块路径判断。直接加载发行目录采用 `standard`；TH、PLE 的外置接入配置显式选择 `shared`，保留其跨 main/renderer 的共享原生状态。renderer 的原生调用仍在 Utility 执行器中，不在不受信任的页面进程加载 DLL。`standard` 当前没有独立的宿主 libuv 泵，因此 `napi_get_uv_event_loop` 明确返回失败，不能借用其他上下文的全局循环；依赖该循环或直接调用 `uv_default_loop` 的原生接入须使用 `shared`。这项边界不影响同步 Node-API。

宿主支持对象及 External 的 128 位 Node-API type tag。`napi_create_external_buffer` 返回 `napi_no_external_buffers_allowed`，且不接管内存/调用 finalizer；调用方可通过 `napi_create_buffer_copy`（例如 node-addon-api 的 `NewOrCopy`）明确选择复制。不能用隐式复制冒充外部内存别名，也未据此提升声明的完整 Node-API 版本。

选定应用后，主进程和独立 renderer addon 服务按实际 `appPath` 授权原生模块：
目录应用允许 canonical 子路径，ASAR 应用只允许归档声明为 unpacked 的成员。
符号链接越界、其他应用目录和未声明成员不会因同进程缓存而获得授权。
此范围独立于 DLL 资源重定向目录；加密归档公钥随应用配置传入，并在对应服务
上下文结束时撤销。应用内模块无需全局 `--allow-external-xenon-node-addons`。
权限拒绝和已找到文件后的加载失败保留 `ERR_ACCESS_DENIED` / `ERR_DLOPEN_FAILED`，
不会再伪装成模块缺失。官方原包的实测结果见 [兼容性验证](Electron原包兼容性验证.md)。

标准 `resources/app(.asar)`、macOS bundle 和根 `package.json` 优先解析。
如果根目录没有入口，运行时会检查一级子目录中的标准发行布局，支持版本目录下的发行文件。
只有一个有效候选时自动选用；多个候选会列出路径并要求指定目录，不按版本名或应用名称猜测。
扫描有 1024 个目录上限，不跟随符号链接或 junction。该入口发现属于运行时行为，导入工具仍只负责原样复制和清单校验。

主进程支持标准 CommonJS、JSON 与 V8 ESM 模块图，包括 `.mjs` / `type:module`、
静态及动态 import、循环与 live binding、JSON import attributes、`import.meta`、
同步 `require(ESM)` 与顶层 await。顶层 await 完成前不向 renderer 宣布应用就绪；
异步入口拒绝会记录启动错误并退出应用容器。包含顶层 await 的模块不能同步 require，
按 `ERR_REQUIRE_ASYNC_MODULE` 报错。CommonJS 命名导出使用官方 cjs-module-lexer 静态分析，
链接阶段不执行业务 CommonJS。

两端共享 package `exports` / `imports` 解析，保留 JSON 条件顺序、通配符、self-reference、
封装及精确文件目标。Renderer 的 Node 加载器仍仅支持 CommonJS；Node ESM 和 `.mjs` preload
明确报错，网页原生 ESM 则继续由 Chromium 处理。完整边界见
[IPC bootstrap 源码组织](../resources/ipc/README.md)。模块格式支持不代表完整 Node API 或 Node/V8 原生 ABI 已实现。

Chromium 在执行 Electron main 之前已经锁定协议表。因此自定义协议权限需要在外置 `privilegedSchemes` 中预先声明，并重启宿主。main 中的 `protocol.registerSchemesAsPrivileged` 允许在 app ready 前多次调用，每次核验请求与启动时实际应用的权限一致；未声明、权限不匹配或不支持的权限会明确报错。修改声明后，仅关闭并重开 Electron 窗口不够。协议权限是浏览器进程级声明，尤其 `bypassCSP` 应只授予应用实际需要的协议。

协议权限声明与请求处理器是独立能力。`session.protocol.handle`、`unhandle`、`isProtocolHandled` 按真实 StoragePartition 路由导航和子资源；顶层 `protocol` 使用默认 Session。普通自定义协议可以直接注册处理器，不因此获得 `standard`、`secure` 或跨域权限。内建 `file:` 支持 Session 内拦截，并优先于默认文件/ASAR 加载器；HTTP(S) 等其他内建协议的拦截仍明确报错。

旧式 `registerFileProtocol` 支持返回文件路径或包含 `path`、`headers`、`mimeType`、`charset`、`statusCode`、`method`、`referrer` 的响应对象，也支持 `{error: 负网络错误码}`；`unregisterProtocol` 和注册状态查询按 Session 隔离。普通文件、标准/加密 ASAR 和 unpacked 成员均在原生端流式读取，保留 Range，不把文件整体传回 JS。`protocol.handle` 支持二进制 `Response`、`Response.error()`、取消与超时；缓冲请求/Response 体有 32 MiB 上限，文件路径响应不受该缓冲上限影响。流式请求、文件上传、跨协议重定向和旧式 `registerBufferProtocol` 等尚未实现的处理器类型仍明确报错。

当前应在创建窗口或导航之前注册处理器。Chromium 已创建的 renderer 非网络 factory 列表不会随处理器增删自动刷新，现存页面动态替换处理器仍需补齐；新导航使用当前注册状态。上述新增文件协议能力处于源码验证阶段，正式原生/产品验证以 [兼容性验证](Electron原包兼容性验证.md) 中对应版本记录为准。

`codeCache` 属于性能优化，允许布尔值声明但不启用缓存；原生解析器不会将其写入有效权限或子进程快照，请求开启时日志逐协议提示 disabled。`allowServiceWorkers` 和 `stream` 属于未实现的功能权限，只接受 `false`，`true` 返回 `ERR_NOT_SUPPORTED`。不会接受开启后再静默删除权限；依赖自定义协议 Service Worker 的应用功能尚不支持。

降级不改变 `standard`、`secure`、fetch/CORS 或 CSP 权限：这些仍须与启动时真实注册的声明完全匹配。运行期新增权限无法绕过 Chromium 的协议表锁，仍需外置 descriptor，或重构应用 main 与浏览器初始化顺序。实现不按应用名称写死 scheme，也不修改发行包源码。

`app.getPreferredSystemLanguages()` 读取真实系统语言偏好：Windows 使用 GlobalizationPreferences（失败时读取系统 UI 语言列表），macOS 使用 CFLocale，Linux 使用 GLib 的 LANGUAGE/LC_ALL/LC_MESSAGES/LANG 解析。不使用应用 `getLocale()` 的值代替系统语言；Linux 的 C-only 环境可以返回空数组，不具备查询能力的平台会明确报错。

Session 按 BrowserContext、容器和 partition 隔离，`persist:` 分区持久化，其他分区使用内存存储。窗口和 guest 在创建 WebContents 前绑定分区；frame / Service Worker preload 从注册表读取，服务断开时撤销。隔离 preload 通过 ContextBridge 暴露 API，页面不直接获得 Node 或宿主 IPC。完整 Electron API 支持范围见 [TH 接入说明](thunder_2025接入Electron容器.md)。

此入口不要求在 C++ 中注册新的应用名称。当前新增项目通过命令行选择目录，未实现自动扫描目录或新增侧栏启动列表。标准发布包按自身 `package.json` 解析入口；无需应用专用 URL 重写。

## 构建与安装包一致性

自动复制及安装包选择目前只支持启用 `enable_xenon_service` 的 Windows 构建，其他平台保持 `xenon_electron_apps = []`；本次不扩展 macOS 应用打包。

导入后执行 `gn args out/Release_64`，保留已有参数，并选择需要附带的应用。例如同时附带
TH、PLE、draw.io、MarkText 和 Motrix：

```gn
xenon_electron_apps = [ "thunder_2025", "xenon_player", "drawio", "marktext", "motrix" ]
```

仅附带三个公开应用时使用 `[ "drawio", "marktext", "motrix" ]`，不带应用使用 `[]`。
其他项目可填本地资源子目录名（如 `"example"`），无须增加产品专用 GN 分支。
目录名必须是单个名称，不能带路径分隔符；对应发行目录必须已经完整导入。

修改选择或导入目录后执行 `gn gen out/Release_64`，再构建。移除本地目录前也应从列表移除对应项。外置同名 `*.xenon.json` 和 `*.asar-public-key.pem` 存在时会随所选应用复制与打包，标准 Electron 应用不要求这两个文件。

生成并校验完整安装器使用统一入口：

```powershell
python xenon_overlay/tools/package_windows.py --build-dir out/Release_64
```

浏览器二进制已完成编译和运行验证、仅调整负载时，可加 `--repack-existing`，只重新归档
并链接安装器。该模式不会编译浏览器源码，也不会安装或启动应用。安装器文件名从 GN 的
品牌/版本配置读取，以命令输出 `report.json` 的 `installer.path` 为准，不一定名为
`mini_installer.exe`。完整说明见 [Windows 打包工具](../tools/windows_packaging.md)。

draw.io、MarkText、Motrix 的宿主制品分别位于工程 `xenon_overlay/resources/` 下同名
目录；构建输出和安装后的应用根目录保持为 `drawio/`、`marktext/`、`motrix/`，各自
内部的 `resources/app.asar`、`.asar.unpacked`、native/helper 和许可证原样保留。
同名外置 `.xenon.json` 与这些目录并列，不包含开发机绝对路径。

`copy_runtime_tree.py` 默认将本地导入的资源目录按原路径增量镜像到构建输出，清理源目录
中已经不存在的文件，保留空目录；depfile 同时跟踪文件和目录。draw.io、MarkText、Motrix
使用该完整镜像规则，源目录已按审查结果去除重复引擎，镜像时不做二次裁剪。
TH/PLE 另有显式 Windows hosted profile，移除由宿主提供的重复运行时，
资源目录中的原始发行包保持完整，详见 [Windows hosted 策略](../tools/windows_electron_runtime.md)。
停止 Git 跟踪不会删除本地导入目录，也不会自动改变应用内部路径。

安装包通过通用 `--xenon-payload-directory` 声明应用目录，通过 `--xenon-payload-file` 声明外置宿主文件。GN 中这些声明及包装脚本受 `enable_xenon_service` 控制。`--xenon-payload-source=<输出相对目录>=<工程源目录>` 在暂存前及压缩前检查源目录、构建输出和暂存内容的一致性。

使用完整镜像规则的应用如果在构建输出中生成日志、状态文件或改变发行文件，安装包流程
会因源/输出不一致而失败。停止对应应用后可重新同步完整发行目录，再打包，避免运行时数据
混入发布目录。TH/PLE 的 hosted 暂存直接读取工程资源中的原始发行包并应用显式 profile，
不读取或清理运行中应用的输出缓存。

`--xenon-staging-only` 走实际 Chromium 暂存和一致性校验，在压缩前退出，用于快速检查打包布局。

## 替换与回滚

预检会拒绝源/目标重叠，以及路径祖先或目录树中的链接、junction。工具在目标的同一父目录创建临时目录，完成复制及源/副本双向哈希复核后，先将旧目标改名为备份，再将临时目录改名为目标。

如果安装改名或外置清单替换失败，工具恢复旧目标；如果回滚本身遭到锁定，报错会给出保留旧目录的备份路径。成功后的备份清理失败会明确报警并保留备份。此流程处理运行期间可报告的文件操作失败，不承诺跨断电的多路径事务。

不要在应用运行并锁定文件时替换目录。输入必须是已完成的静态发行制品，不应指向正在构建的工作目录。
