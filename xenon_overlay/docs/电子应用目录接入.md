# Electron 应用目录接入

## 导入契约

导入的对象是**已经组装完成、版本一致的发行目录**。适配层保留输入目录内的所有相对文件路径和文件字节，最终打包输出也应保持同一布局。

`tools/import_electron_app.py` 是通用导入工具，没有应用名称、可执行文件名称或 native 文件名分支。它：

- 原样复制 ASAR、加密 ASAR、`.asar.unpacked`、`.node`、DLL 和其他发行文件；不解包、不重打、不修补 JavaScript。
- 不把 native 同时复制到根目录、`build/`、`build/Release/`，也不拆分 main、preload 和 renderer。
- 记录空目录，按相对文件路径、长度及 SHA-256 检查结果；不靠时间戳判定内容一致。
- 明确拒绝 symlink、Windows junction、其他 reparse point 以及普通文件/目录之外的对象。当前版本不支持链接保留，不能通过跟随链接或展开目标来悄悄改变布局。
- 要求导入期间输入目录稳定；输入变化或复制结果不一致时，在替换前失败。

该工具确认导入完整性，不代替应用发布验证：它不会解密归档来验证 `main`，也不会加载 `.node` 判断 ABI、检查插件配置是否缺件，或证明供应方二进制来自某个提交。

## 使用方式

在源码根目录运行：

```powershell
python xenon_overlay/tools/import_electron_app.py `
  --src F:/releases/example/1.2.3 `
  --out H:/chromium_142/src/xenon_overlay/resources/example `
  --manifest H:/chromium_142/src/out/import-manifests/example.json
```

`--out` 是**目标应用目录本身**，不是多个应用的公共父目录。目标旧目录会在新目录复制、哈希校验完成后被整体替换，因此旧发行中已删除的文件不会残留。

工具识别并记录以下入口候选，保留原始 `package.json`：

| 输入布局 | 检测标志 |
| --- | --- |
| Electron 发行目录，应用为归档 | `resources/app.asar` |
| Electron 发行目录，应用为目录 | `resources/app/package.json` |
| 无链接的 macOS bundle | `Contents/Resources/app.asar` 或 `Contents/Resources/app/package.json` |
| 单独的应用目录 | 根目录 `package.json` |

同一目录有多个候选时，清单记录所有候选，不猜测厂商定制启动器的优先顺序。归档保持不透明；例如 `resources/app/package.json` 指向 `out.asar/main.js` 时，`out.asar` 仍只是被原样复制的发行文件。

`--manifest` 可选。清单必须位于源目录和目标目录之外，避免宿主记录成为应用负载的一部分。清单包含检测到的布局、源/目标路径，以及所有相对文件路径、大小、SHA-256 和目录；不包含文件正文。

导入后或最终打包后进行只读比较：

```powershell
python xenon_overlay/tools/import_electron_app.py `
  --src F:/releases/example/1.2.3 `
  --out H:/chromium_142/src/out/Release_64/example `
  --check
```

一致返回退出码 `0`；有增删、内容变化、目录差异或读取错误时返回非零。`--check` 不复制文件、不生成清单，可用于验证资源目录与最终输出目录完全一致。不能同时使用 `--check` 和 `--manifest`。

旧脚本名保留为薄入口：

```powershell
python xenon_overlay/tools/sync_thunder_2025.py --src F:/releases/thunder --out xenon_overlay/resources
python xenon_overlay/tools/sync_xenon_player.py --src F:/releases/player --out xenon_overlay/resources
```

这两个入口的 `--out` 为父目录，分别导入其下的 `thunder_2025` 和 `xenon_player`；不传时使用仓库的 `xenon_overlay/resources`。`--src` 现为必填的完整发行目录。旧 `--player-sdk`、`--native-dir`、`--plugins-dir`、重打归档及忽略文件等参数会直接报错。`sync_xenon_player_frontend.py` 已退役，执行只返回错误及完整目录导入指引，不会创建 `frontend/`。

## 外置宿主配置

导入清单记录复制结果；宿主配置控制如何启动应用，两者用途不同。工具不生成或改写宿主配置，也不把宿主配置、公钥自动塞进应用目录。

启动入口接受绝对路径：

```powershell
xlb153.exe --xenon-electron-app=H:/applications/example
xlb153.exe --xenon-electron-app=H:/applications/example/resources/app.asar
xlb153.exe --xenon-electron-app=H:/applications/example.xenon.json
```

无需覆盖入口或其他宿主配置时可直接使用发行目录、应用目录或 ASAR。需要覆盖时，在应用目录外提供 JSON，例如：

```json
{
  "application": "example",
  "executable": "example/application.exe",
  "main": "out.asar/main.js",
  "archivePublicKey": "example.asar-public-key.pem"
}
```

| 字段 | 含义及路径基准 |
| --- | --- |
| `application` | JSON 配置必填；发行目录、应用目录或 ASAR。相对路径基于 JSON 所在目录。 |
| `executable` | 可选的已存在应用可执行文件，用于应用身份及路径语义；相对路径基于 JSON 目录。不指定时使用宿主可执行文件。 |
| `main` | 可选入口覆盖，相对于解析后的应用根目录；例如发行根解析到 `resources/app` 后，`out.asar/main.js` 在该 app 目录内。 |
| `archivePublicKey` | 可选公钥文件，相对路径基于 JSON 目录。只接受运行时支持格式的公钥，不需要私钥。 |
| `name`、`version` | 可选名称和版本覆盖，默认来自应用元数据。 |
| `versionFromExecutable` | 可选布尔值；开启后从应用可执行文件读取版本，覆盖 `version`。平台或文件无法提供版本时会报错，不自动猜测。 |
| `parentWindowPairing` | 可选字符串数组，声明需要与父窗配对的页面路径。路径相对于解析后的应用根目录。 |

`main` 和 `parentWindowPairing` 必须是应用内相对路径，不允许绝对路径或 `..`。加载器拒绝未知字段和错误字段类型。应用本身的 `package.json`、ASAR、preload、`.node` 保持发行字节不变。

保留完整发行布局不等于支持任意 Electron 应用。应用依赖的 Electron/Node API 必须已由兼容层实现，native 模块也必须与当前运行时 ABI 兼容；导入器不补写不存在的 API，也不转换 native 二进制。

此入口不要求在 C++ 中注册新的应用名称。当前新增项目通过命令行选择目录，未实现自动扫描目录或新增侧栏启动列表。标准发布包按自身 `package.json` 解析入口；无需应用专用 URL 重写。

## 构建与安装包一致性

`copy_runtime_tree.py` 将资源目录按原路径增量镜像到构建输出，清理源目录中已经不存在的文件，保留空目录；depfile 同时跟踪文件和目录。不会按应用或 DLL 名称排除文件。

安装包通过通用 `--xenon-payload-directory` 声明应用目录，通过 `--xenon-payload-file` 声明外置宿主文件。GN 中这些声明及包装脚本受 `enable_xenon_service` 控制。`--xenon-payload-source=<输出相对目录>=<工程源目录>` 在暂存前及压缩前检查源目录、构建输出和暂存内容的一致性。

应用运行可能在构建输出中生成日志或 SDK 状态文件。出现新增文件、文件变更或缺件时，安装包流程会失败并要求重新同步，避免将运行时数据混入发布目录。停止应用后可使用通用导入/镜像工具恢复发行目录，再打包；没有按 TH/PLE 文件名编写过滤规则。

`--xenon-staging-only` 走实际 Chromium 暂存和一致性校验，在压缩前退出，用于快速检查打包布局。

## 替换与回滚

预检会拒绝源/目标重叠，以及路径祖先或目录树中的链接、junction。工具在目标的同一父目录创建临时目录，完成复制及源/副本双向哈希复核后，先将旧目标改名为备份，再将临时目录改名为目标。

如果安装改名或外置清单替换失败，工具恢复旧目标；如果回滚本身遭到锁定，报错会给出保留旧目录的备份路径。成功后的备份清理失败会明确报警并保留备份。此流程处理运行期间可报告的文件操作失败，不承诺跨断电的多路径事务。

不要在应用运行并锁定文件时替换目录。输入必须是已完成的静态发行制品，不应指向正在构建的工作目录。

## 现有 TH / PLE 的发布来源注意事项

以下记录解释当前本地制品的来源差异，不属于导入工具中的产品规则。

### TH

`F:/thunder_2025/bin/Release/resources/app/out.asar` 是完整标准包，其中 268 个文件已逐一与当前拆分的 `out/` 和 `renderer.asar` 比较，内容一致。可将完整归档作为主包输入，避免再拆 main/preload/renderer。
